# go-web-openapi

Describe the Go service's API in OpenAPI and generate the TypeScript
client the React application uses.

## Why

The React application and the Go API must not drift apart; a typed
client generated from one description keeps them in step.

## Scope

- `webapi/openapi.yaml`, kept next to the handlers and checked against
  them in tests (each route described, each described route served).
- The generated client goes to `web/app/src/api/generated/` (the
  React application lives in `web/app/`), committed, regenerated by
  `npm run gen:api` from `webapi/openapi.yaml` with openapi-typescript
  (types) and openapi-fetch (typed fetch), versions pinned in
  `web/app/package-lock.json`. The application calls the API only
  through it.
- A check that regenerating the client from the description gives no
  diff.
- `web/docs/` points at the description as the API contract.

## Design notes

- No network at build time: the generator runs from a pinned image or
  a vendored tool.

## Depends on

Nothing.

## Done when

- The description covers every Go route, a test fails if a route and
  the description disagree, the generated client compiles, and
  regenerating it gives no diff.
